# CLAUDE.md — roki (container `roki-ee`)

Phoenix 1.8 / LiveView app serving **https://roki.ee** (and `www.roki.ee`).
You are inside the container at `/www/app`. An empty PhoenixKit scaffold with
no product decided yet; created 2026-10-22 as a copy of `fabledex-com`'s shape
(sibling stack in the same cluster), itself shaped after `forksight`. Host-side
reasoning lives in server-agents1 `adrs/0005` (edge), `0006` (shared Postgres),
`0009` (test databases) and their 2026-08-23 amendments.

Phoenix 1.8 / LiveView conventions for this codebase are in `AGENTS.md`
(generated by `phx.new`). This file is only about what is different **here**.

## The one thing that will waste your time first

The container exports `PHX_SERVER=true` and `PORT=4000`, and supervisord is
already running the server on that port. So **any mix task that boots the
application dies with `:eaddrinuse`** — `mix run`, `iex -S mix`,
`mix phoenix_kit.doctor`, `mix phoenix_kit.*`. It is not a broken install.

Prefix such commands to keep them from opening a listener:

```bash
PHX_SERVER=false mix phoenix_kit.doctor
PHX_SERVER=false mix run -e 'IO.inspect(...)'
```

`mix test` needs no prefix — `config/runtime.exs` forces `server: false` in
`:test` as its LAST block, specifically so the dev server's `PHX_SERVER`/`PORT`
cannot leak into the suite.

## Configuration — the contract

**Everything comes from the container environment**, read in ONE place:
`AppConfig.load/1` in `config/runtime.exs` (Dotenvy). `dev.exs`/`test.exs` hold
no connection settings and no secrets. Required (`env!(..., :string!)`, boot
fails if missing): `DB_USERNAME DB_PASSWORD DB_DATABASE SECRET_KEY_BASE
LIVE_VIEW_SIGNING_SALT`. Optional with defaults: `DB_HOSTNAME` (pgbouncer),
`DB_PORT` (5432), `DB_POOL_SIZE` (10), `TEST_DB_HOSTNAME` (postgres),
`TEST_DB_DATABASE` (DB_DATABASE + `_test`), `PORT` (4000), `PHX_HOST`,
`PHX_SERVER`, `SERVER_ORIGINS`.

**NEVER create `.env` / `.env.test` in this repo.** The container environment is
last in Dotenvy's source order and wins, so such a file is silently ignored — a
committed `.env.test` means the suite runs against the DEVELOPMENT database.
The `phoenix-dotenvy-config` skill under `/www/elixir_app_helpers` (read-only
mount) instructs exactly that — **that step does not apply here.** Real values
live in the stack's `.env` on the host, which you cannot see from in here.

- `MIX_ENV` is NOT set anywhere — not in the image, not in supervisord, not in
  compose. Plain `mix test` selects `:test` itself. Do not set it.
- `mix ecto.create` can never work: the role is `NOSUPERUSER`/`NOCREATEDB` and
  Ecto reaches the maintenance database first, where `CONNECT` is revoked from
  `PUBLIC` on purpose. Granting `CREATEDB` does not fix it. The `test:`,
  `ecto.setup:` and `ecto.reset:` aliases all deliberately omit it. New
  databases are provisioned by an operator on the host
  (`platform/stacks/postgres/newdb.sh`, `newtestdb.sh`).

## Databases

Two, on the host's single shared Postgres 18 (`pgvector/pgvector:pg18`):

| | Database | Endpoint | Why |
|---|---|---|---|
| dev | `roki_fr` | `pgbouncer:5432`, `prepare: :unnamed` | pooled, transaction mode |
| test | `roki_fr_test` | `postgres:5432` DIRECT, SQL sandbox | the sandbox holds one transaction open across statements, which transaction pooling cannot pin to a single backend |

Both carry `citext`, `pg_trgm`, `pgcrypto` — installed at creation because
`CREATE EXTENSION` needs superuser, so migrations cannot add them later.

Two consequences of sitting behind a transaction pooler:

- **A migration doing DDL may need `@disable_ddl_transaction true`.** The V205
  baseline ran fine, but `mix phoenix_kit.doctor` flags the risk for new ones.
- **`LISTEN`/`NOTIFY` does not survive the pooler.** Oban is therefore
  configured `notifier: Oban.Notifiers.PG` (see the note in `config/config.exs`)
  — the default Postgres notifier fails *silently*: jobs still run, but queue
  pause/resume/scale signals are dropped. If you add `Phoenix.PubSub`'s Postgres
  adapter, or session advisory locks, or `WITH HOLD` cursors, switch
  `DB_HOSTNAME` to `postgres` — which is an operator change to the stack `.env`,
  and needs `docker compose up -d` (not `restart`) to take effect.

## Operating the app

supervisord (PID 1) owns the server. **Docker commands do not work in here.**

```bash
supervisorctl status
supervisorctl restart elixir      # after config/*.exs or dep changes
tail -f /var/log/elixir.log
```

Do not start `mix phx.server` by hand — you would collide with the supervised
one, and it would not survive your shell.

```bash
mix test                  # `test:` alias runs `ecto.migrate --quiet` first
mix precommit             # compile --warnings-as-errors, deps.unlock --unused, format, test
mix assets.build          # after touching assets/
```

Run `mix precommit` before calling a change done.

## phoenix_kit

`{:phoenix_kit, "~> 2.0"}` — currently 2.54.2, database at **V209**, ~182
tables. Wired in `lib/roki_web/router.ex` (`import PhoenixKitWeb.Integration`,
`PhoenixKitWeb.Plugs.Integration`, `phoenix_kit_routes()`) and started in
`lib/roki/application.ex`. Auth lives under `/phoenix_kit/...`
(`url_prefix`), e.g. `/phoenix_kit/users/register`.

It has its own plugin system — the `PhoenixKit.Module` behaviour plus
`PhoenixKit.ModuleDiscovery` — by which a package registers admin tabs,
permissions, routes, supervisor children and versioned migrations. Start at
`deps/phoenix_kit/lib/phoenix_kit/module.ex`. Note `ModuleDiscovery`'s beam scan
only walks deps that depend on `:phoenix_kit`, so a module defined in THIS app
must be listed explicitly in `config :phoenix_kit, modules: [...]`.

**`:igniter` is a dev/test dep on purpose.** `mix phoenix_kit.install` and
`mix phoenix_kit.update` refuse to patch code without it, and PhoenixKit
declares it `optional: true`, which is not resolved transitively.

### `PHX_SERVER=false mix phoenix_kit.doctor` — the four standing warnings

27/31 pass (PhoenixKit 2.54.2 has two more checks than ledraw's 2.41.4 had). The
four that remain are understood; do not "fix" them:

1. **PgBouncer Detection** — advisory. The Oban consequence it warns about is
   already handled above.
2. **Schema-Declared Relations Without a DB FK** (2 of 37) —
   `phoenix_kit_activities.actor_uuid` / `target_uuid`. Upstream PhoenixKit's
   own schema: a polymorphic target cannot carry a foreign key. Not ours.
3. **daisyUI Version** — a false positive on the *path*. It looks for
   `assets/vendor/daisyui.js`; phx.new 1.8 instead pins daisyUI as a sparse
   github dep and `assets/css/app.css` loads it from
   `deps/daisyui/packages/bundle/`. The version is **5.7.46**, comfortably above
   the 5.6.0 PhoenixKit wants (phx.new's own default was 5.5.20, which was
   below it — that is why the tag in `mix.exs` is pinned higher).
4. **Sitemap Discoverability** — `priv/static/robots.txt` already carries the
   `Sitemap:` line; what remains is the `site_url` *setting* (a row in
   `phoenix_kit_settings`, not config), which is unset so sitemap links use the
   endpoint URL. Set it from the admin settings page once there is a site worth
   crawling; nothing to do in code.

The fifth warning the first run showed, **Integration Key**, was cleared on
2026-10-06 with `mix phoenix_kit.integrations.rotate_key` (see Secrets hygiene).

## Theming

`lib/roki_web/components/layouts/root.html.heex` ships phx.new's own
`data-theme` bootstrap (localStorage `phx:theme`, falling back to
`prefers-color-scheme`). PhoenixKit's competing bootstrap is deliberately NOT
installed — two scripts stamping the same attribute fight, and the host's
`[data-theme=...]` styles stop applying. `config :phoenix_kit,
dashboard_themes: ["light", "dark"]` points the kit's admin pages at the same
two palettes, and the `<%!-- phoenix_kit: theme managed by host --%>` comment in
`<head>` is the documented opt-out that stops the installer re-offering it.

## Secrets hygiene

- **Core dumps are disabled on every path** (image `ulimit -c 0`, limits.conf,
  and the compose `ulimits` block which is the ONLY thing covering
  `docker exec` sessions). This host's `kernel.core_pattern` is the bare name
  `core` and is not namespaced, so a crash with `CWD=/www/app` would write the
  whole process environment — `DB_PASSWORD`, `SECRET_KEY_BASE`,
  `LIVE_VIEW_SIGNING_SALT` — in cleartext into this git tree. That happened on
  this host on 2026-08-23. If you ever see a `core*` file here: delete it and
  say so.
- **Integration credentials have their own encryption key**, at
  `/root/.config/phoenix_kit/roki-integrations.key` (mode 600). Without it
  they would be encrypted under a key derived from `secret_key_base`, which also
  signs sessions and CSRF tokens. `/root` is a bind mount, so the key survives a
  container recreate — the writable layer does not. Rotate with
  `PHX_SERVER=false mix phoenix_kit.integrations.rotate_key`, then restart
  promptly: rows are re-encrypted immediately and reads fail until the restart.
- Never write credentials into `config/*.exs`, supervisord `environment=`, or
  any committed file. `core*` and `.env*` are gitignored.

## This stand serves MIX_ENV=dev to the public internet

Deliberate, on the owner's call — but know what it means. Every other apex on
this host runs the prod image with a separate `dev.*` sibling; this is a single
dev container on the apex, so:

- **`check_origin` is `false`** (both `dev.exs` and `runtime.exs` set it for
  `:dev`). The LiveView websocket accepts ANY `Origin` — verified: a handshake
  with `Origin: https://evil.example` returns `101`. `SERVER_ORIGINS` is
  therefore inert today and only starts being enforced if this moves to the prod
  image.
- `debug_errors`, `code_reloader` and the `/dev/dashboard` + `/dev/mailbox`
  routes are live, behind no authentication.

Fine while this is an empty scaffold. It needs revisiting before real user
accounts exist, and PhoenixKit's auth is already wired up. The open question the
host records about authentication on publicly-served dev stands (`adrs/0008`) is
this question.

## Toolchain

Elixir 1.19.6 / OTP 28 (`erts-16.4.0.5`), the image's system runtime at
`/usr/local`. `MIX_HOME` is `~/.mix` = `/root/.mix`, which is a **bind mount** —
so `hex`, `rebar` and the `phx_new` archive installed there survive a container
recreate. Anything installed outside a bind mount lives only in the writable
layer, and `docker compose up -d` discards it.

`git` needs `safe.directory` here: `/www/app` is `ubuntu:ubuntu` (the image
chowns `/www` at boot) while `docker exec` lands you as root. It is already set
in `/root/.gitconfig`.

**Before any `docker compose up -d` on this stack** (an operator action, from
the host): the compose file pins `elixir-19-otp-28-dev:latest`, and `:latest`
moves on this host. Check `docker inspect -f '{{.Image}}' roki-ee` against
`docker images` first — a silent runtime upgrade forces a full recompile while
the app is serving. `forksight-dev` hit exactly this.

## Laev (optional per-user connection)

`laev` (hex, 0.1.40) is a dependency; it declares Elixir `~> 1.20` but compiles on this
image's 1.19.6 with only a warning. `Roki.Laev` runs everything inside a per-user
`Laev.Scope` rooted at `<home>/laev-users/<user uuid>` (`/root/laev-users` = `data/roki-ee/root/`
on the host). An account starts **not connected**; the home page (`RokiWeb.HomeLive`) lets a user
paste their own laev key, which laev saves in that directory (`config`, mode 600) — there is no
table and no copy of the key anywhere else. Accounts are never linked to each other or to a
key without that user pasting it. Sync carries history and, only if the user ticks "bring my
API keys", their encrypted API keys; **preferences (player, language) do not sync**.
Scope is process-bound: call `Roki.Laev` from `start_async`, never from a shared process.

## Routes

`/` → redirects (own `/:username/home` when signed in, else `/home`). `/home` — public Featured
page (`FeaturedLive`, cached 12 h by `Roki.Featured`; needs `TMDB_API_KEY` in the stack `.env`,
which `config/runtime.exs` hands to laev as `config :laev, tmdb_key:`). `/:username/home` —
that signed-in user's own shelf (`UserHomeLive`); anyone else is sent to `/home`, a visitor to
the login. These live in the `:site` live_session ahead of `phoenix_kit_routes()` so they win
over PhoenixKit's own `/:group` catch-alls. A `runtime.exs` change needs `docker restart roki-ee`.

`/search?q=` (`SearchLive`, `Roki.Search`) — TMDB title search with a year hint (`heat 1995`) and IMDb ids.
It runs in the signed-in user's laev scope when they have connected (their own TMDB key, their own
marks), else in the shared `_featured` scope (server key). **Watched** = laev's own rule via
`Laev.Shelf.seen?/1` (a film played through or marked; a series only when marked; an anime when every
MAL entry is) — `Roki.Laev.seen_keys/1,2` — and the poster component greys it with a tick. Only for a
connected user; visitors never get marks.

## Search throttling, spelling, lists

`Roki.Search` ports laev's private search logic: spelling variants (gray/grey, color/colour, theater/
theatre, harbor, armor, honor), the year hint (`heat 1995`, +-1 soft), exact-title-first ranking, IMDb
ids. **Throttle:** results are cached 10 min in `Roki.TTLCache` (ETS, single-flight, hard cap 2000
entries, only `{:ok, _}` kept); a cache *miss* spends from `Roki.RateLimit` (Hammer ETS) — 20/min per
client (`RokiWeb.Client`: user uuid, else the `X-Forwarded-For` IP, needing `:peer_data`/`:x_headers`
in the endpoint `connect_info`) and 300/min site-wide. List posters have their own budget (6/min per
client, 60/min site-wide, only when cards are missing). Counters are per-node, reset on restart.
Changing the supervisor or `connect_info` needs `docker restart roki-ee`.

**Lists** (`/lists`, `/lists/:slug`, `Roki.Lists`) — laev's 11 curated franchises (`Laev.Franchises`)
plus TMDB *collections* (slug `collection-<id>`, found from search results). **Not** TMDB's
user-made lists, which laev does not know about. A list opens complete from the curated file; posters
come from laev's card cache (per scope dir — the shared `_featured` scope when a server key is set, so one
cache serves everyone). Some lists carry their own tier keyed `all` (Marvel) — `tabs/1` in `ListLive`
handles that. Search offers matching lists above the first page of results.

## Stats, calendar, the pulse

`/:username/stats` (`StatsLive`, `Roki.Stats`), `/:username/calendar` (`CalendarLive`, `Roki.Calendar`);
the three user pages share `RokiWeb.UserTabs` and are gated by `RokiWeb.UserGuard`.

**Stats must never run without a TMDB key.** Laev times films/shows from TMDB runtimes cached in the
scope's `runtimes.json`, and a failed lookup is cached as `"unknown"` *forever*. Run keyless (as the shelf
once did before the user's keys had synced) and every film/show is remembered as zero-length: the owner's
6,940h read as 2,500h. `Roki.Stats.build/0` therefore refuses without a key and `heal_runtimes/0` clears a
cache that is >50% unknown (anime lengths, from MAL, are kept). Don't call `Laev.Stats.all_time/0` directly.
Only `Roki.Stats.for_user/1` (rate limited, 4/min) should be used. The first measurement is ~1,450 TMDB
lookups (about a minute for a big library); later ones are instant. The shelf loads stats and the pulse in
separate async tasks after the shelf itself, so they never delay it.

**Day logs can be corrupt.** Synced `watched/*.log` files can have entries fused onto one line
(`2026-10-22 12026-10-22 2`); laev's own `Laev.Days` parser reads that as 12,026 s and reported 245,000 h.
`Roki.Stats.day_totals/0` re-parses with a lazy-digit regex that splits them and caps a day at 24 h.
(Likely a laev sync bug: the log is rewritten without its trailing newline, so the next append fuses.)

**Calendar** = the user's *Saved* list (laev's rule), ported from `Laev.Calendar`: AniList for anime,
TMDB seasons for TV, TMDB release dates for films. Laev's own keeps a 7-day look-back in the machine's
`/tmp` (RAM here); ours keeps each title's whole schedule in `Roki.TTLCache` for 6 h, shared across users,
never caching a failure, with a 3/min per-client + 20/min site-wide budget for uncached titles. The home
page's pulse ("X drops in 3 days", "Just dropped: Y") is `Roki.Calendar.pulse/1` over the same events.
The logo links to `/home` (the featured page), not `/`.

The header carries only Featured and (signed in) Shelf / Stats / Calendar. **Lists is not a header link**: it is a section at the bottom of `/home` (`FeaturedLive`), shown once the shelves above have settled. `/lists` itself still exists.

**Shows excludes anime** (`Roki.Featured`): a trending-TV title is dropped when `Laev.AnimeMap.anime?/2` (MyAnimeList has an entry) is true, except ids in `@keep_as_shows` (Cyberpunk: Edgerunners). Bump `@version` when what a cached page contains changes.
Shows pages are exactly 20 (`Roki.Featured.shows_slice/3`): the anime-free stream is cut into pages and topped up from the next TMDB page; raw TMDB pages are memoised separately (`{:tv_raw, p}`); overlapping pages are de-duplicated by id.

## Settings

`/:username/settings` (`SettingsLive`) is a form over `Laev.Settings` — laev describes every setting as
data (`all/1`), checks each change (`put/2`) and can ask the real service whether a key works
(`validate/2`). Choices and text save on change; **a key is saved only after `validate/2` passes**
(RD / TorBox / TMDB; the rest are saved as pasted) and is only ever shown masked. The player list
keeps a value this server cannot offer (a terminal `mpv`), since the account may legitimately hold it.
Settings reach the terminal app only when API keys are carried (they travel in the same encrypted
blob); the page says so. The shelf no longer has a Connections section — sync, carry-keys and
disconnect live here. The header link is "Settings"; PhoenixKit's own account settings stay in the
avatar menu. The test config lifts PhoenixKit's registration rate limit (tests register users).

## Study sidebar (`/study`)

The first piece of a language-learning player: a `<video>` on the left and, on the right, every
subtitle line — the spoken line highlighted, kept centred while it plays, free to scroll, a click plays
from that line. Prototype source: a file from the user's computer, a direct URL, or the built-in
demo; subtitles: an uploaded .srt/.vtt/.ass/.ssa (converted to WebVTT by `Roki.Subtitles` using laev's
converters, encoding detected) or the demo. **No JS libraries** — plain DOM, no hls.js / kuromoji yet
(those arrive with the real watch flow; the design to follow is `alexdont/debrid_theatre`).

- `assets/js/study/cues.js` — pure functions (`parseVtt`, `activeIndex` binary search, `liveIndexes`,
  `formatTime`); `assets/js/study/sidebar.js` — the `StudySidebar` hook; CSS `.study-row` in `app.css`.
- Rows are built once; highlighting only flips `data-state` (past/current/future) and `data-live`.
  **Highlighting must never change a row's size** (no bold): a wider font wraps differently and the whole
  list jumps under the reader (caught by the browser test).
- Following: it scrolls the *list*, never the page; a seek jumps, a line coming up in order glides. Any
  wheel/touch/pointer-down in the list stops following (a "Back to current line" pill appears) and it
  resumes after 5 s idle or on click. While playing it runs on `requestAnimationFrame`, not `timeupdate`.
- `allow_upload ... accept: :any` on purpose: LiveView refuses extensions the MIME database does not
  know, and it has never heard of .srt/.ass. The extension is checked in `handle_progress` instead.
- Subtitle files that are neither Unicode nor Latin-1 (e.g. Shift-JIS Japanese) will be read as Latin-1
  and garble; they need a real encoding detector.
- Tests: `node --test assets/js/study/cues.test.mjs` (logic), `mix test` (conversion + page), and
  `NODE_PATH=$(npm root -g) node test/e2e/study.js` (Chromium against the running dev server, 22 checks;
  `ROKI_URL` to point elsewhere, `SHOT=/path.jpg` for a screenshot).

## Watching (the default player)

Every poster leads to `/title/:type/:id` (`RokiWeb.TitleLive`); movies and episodes play there in the study player (video left, subtitle sidebar right). The flow lives in `Roki.Watch`, the screen in `TitleLive`, the player in `RokiWeb.StudyComponents.study_player/1` + `assets/js/study/sidebar.js`.

- **Pipeline** (a Task per Play, results ignored if `token` is stale): subscription check → `Watch.ctx` → `Watch.sources` (TTLCache 10 min; movie/tv/anime paths) → probe 8 releases at a time through the user's debrid (`Laev.Providers.probe_sources` with `notify:`) → `attach_and_rank` → auto-pick (`Watch.auto_choice`) or a list to choose from → `Watch.start`.
- **Cost rule:** h264 is copied into HLS (free); h265/AV1 is re-encoded by libx264 on this server (a 4K one took ~7 cores and 7 GB). So `auto_choice` prefers the best h264/unlabelled release, falls back to a re-encode capped at 1080p, and `start` refuses a re-encode when 2+ ffmpeg are already running (`:busy`). Marked "re-encoded" in the list.
- **Streaming:** laev writes HLS under `$TMPDIR/realdebrid_remux/<id>` — `TMPDIR=/var/cache/remux` (the `cache` dataset: no snapshot/backup, 24 h TTL swept by laev). `/stream/:id/:file` (`StreamController`) serves it to signed-in users only, whitelisted names. hls.js 1.7.3 is vendored at `priv/static/vendor/` (Apache-2.0), loaded lazily; Safari plays HLS natively.
- **hls.js settings matter:** `liveDurationInfinity: false` + `startPosition` — the playlist is EVENT-type while ffmpeg runs, and without these there is no seek bar and resume is impossible.
- **Progress** is posted every 5 s / on pause by the hook (`progress` event → `Watch.record_progress` → laev's own position/watched arithmetic; synced to the terminal app when an episode finishes). Nothing is posted before the resume seek.
- **Chromium in the container** crashes when `TMPDIR=/var/cache/remux`; run Playwright with `TMPDIR=/tmp`.
- `test/e2e/watch.js` is a manual end-to-end that uses a real debrid account and needs a session cookie in `/tmp/e2e-cookie.txt` (see git history of this note); it adds a history entry — clean up with `Laev.Position.forget/2` + `Laev.Resume.delete/2`.
- Known edge: a laev remux worker whose ffmpeg was killed or whose directory was deleted stays registered until its TTL, so replaying that release times out; restart the app or wait.

### External player (VLC / mpv, e.g. on a phone)

A device-level choice, stored in the browser (`localStorage["roki:player"]`) and sent as socket params (`player`, `platform`) — external (VLC) is the default on every device; "Browser" is opt-in. In external mode nothing is remuxed: `Watch.auto_choice_external` applies laev's plain rule (best up to the ceiling, 4K/HEVC allowed) and `Watch.external` writes the history entry and returns the direct debrid link. The panel offers `vlc-x-callback://` (iOS), an Android `intent:`, `vlc://` (desktop), an .m3u download, copy link, Infuse and mpv; Infuse/mpv/desktop-VLC links are untested. An external player cannot report progress, so "Mark as watched" calls `Laev.Position.set_watched`. `test/e2e/external.js` is the manual phone-emulation check (same cookie setup as `watch.js`).

### Settings split

`SettingsLive` shows three kinds: shared laev settings (editable), **site-only** settings (`Roki.Laev.web_settings/1`, stored in `<user dir>/roki-web.json`, removed on disconnect; today only `browser_max_resolution`, default 1080p, shown right under laev's ceiling as two independent ceilings: `Watch.ceiling/4` uses this one in browser mode (never above 1080p) and laev's own (any value) for an external player), and **terminal-app-only** settings (`@cli_only`: player, skip, posters, download dir, mpv args), rendered disabled with a "CLI only" badge and refused server-side. The locked Player row lists vlc / mpv / browser; on this site each device picks its player on the title page.

### Source cache

`Roki.Watch.SourceCache` keeps the ranked, already-probed releases of a film/episode for the user's "Keep found sources" setting (12 h default; off/6/12/24) as files under `<user dir>/roki-sources/` (per user because the links belong to their debrid account; survives restarts, goes on disconnect). A cached Play skips search and probing (≈60 ms) and goes straight to `good`, the release that last started. Retry (`force?`) bypasses both this cache and the shared 10-minute `Watch.sources` list. If a cached release fails to start, the entry is dropped and the search runs again by itself. Posters carry a "⚡ cached" badge via the `RokiWeb.Cached` on_mount (`@cached_titles`); episode rows and the movie hero show it too. Cached debrid links are assumed to stay valid for the window; the failure fallback covers the case they don't.

### Poster progress and hover card

On the shelf (`compact` posters) the caption under the poster is gone: episodes/seasons done (parsed from laev's `note`, "7/13 episodes") and, for a film or episode in progress, the stop position and time left sit in a strip on the poster, with a thin bar. A hover card (`assets/js/peek.js`, mouse only) shows year, length, rating, genres and a short overview from `GET /peek/:type/:id` (`PeekController`: signed-in only, 90 lookups/min, `Watch.title` is cached 12 h), plus the progress/resume/cached lines the page already has (`data-peek-*` attributes). Other pages keep their caption.

### Navigation and the section pages

Header (`RokiWeb.Layouts.app`): logo (= Featured `/home`), then Movies / Shows / Anime (Manga is a disabled placeholder), and on the right search (an icon that opens a box under it; Enter goes to `/search?q=`), calendar and shelf (star) icons for a signed-in user, the theme toggle, and PhoenixKit's account dropdown. Settings and Stats are not in the bar: the dropdown's "Settings" (`/phoenix_kit/:locale/profile/settings`) is redirected by `AccountController` to `/:username/settings`, which links to PhoenixKit's own account page at `/phoenix_kit/profile/settings`; Stats is reached from the shelf's strip.

`/movies`, `/shows`, `/anime` (`CategoryLive`, `Roki.Browse`): a larger-poster grid, Popular (= the Featured list) by default or Newest / Oldest / Top rated (TMDB discover, out already, with a vote floor so the oldest/newest/top are not obscure), grid size S/M/L at the top right (kept in `localStorage["roki:grid"]`, sent as the `grid` socket param), "Load more" at the bottom. Featured shows two rows per kind and "See more →".

The section grids keep to whole rows while more can be loaded (`assets/js/fill_grid.js`, the `FillGrid` hook): the incomplete last row is hidden until the next page fills it, and shown in full once the list ends.

### Title page: library actions

Under the poster (large, well away from Play): Save for later (`Laev.Watchlist`), Put on hold (`Laev.Holds`; not for anime, whose status lives on MyAnimeList), and Mark watched / Mark all watched (`Laev.Position.set_watched`: a film's one mark, or every episode that is out for a series; the same button unmarks). Each episode row has its own mark/unmark toggle and the season header has Mark/Unmark season. All go through `Roki.Watch` (`library/2`, `toggle_saved/2`, `toggle_hold/2`, `set_watched/5`, `set_many_watched/4`, `set_series_watched/3`), clear the stats cache and push to the user's other devices. Above Play: the Browser / External player switch, and Play itself is the big button.

### Rating on TMDB

The title page's fourth button (`Roki.Watch.my_rating/2`, `rate/3`, `clear_rating/2`, through laev's TMDB session; a series is rated as a whole): TMDB's average in orange and, once rated, "You 7.5" under it in blue. Needs the user's TMDB account linked in laev (`Laev.Tmdb.account?`); otherwise the sheet says so. Episode ratings (`Laev.Tmdb.rate_episode`) are not wired yet.

## The watch flow (replaces the single-page Play described above)

Pages, in order — nothing plays on the title page any more:

1. `/title/:type/:id` (`TitleLive`) — the title. A film's Play → sources; a series' Play → episodes.
2. `/title/tv/:id/episodes` (`TitleLive`, `:episodes`) — season picker, episodes with watched marks, per-episode Play → that episode's sources (`?auto=1`).
3. `/sources/movie/:id`, `/sources/tv/:id/:season/:episode` (`SourcesLive`) — searches and checks the releases (`Roki.Watch.Resolver`, source cache first). Arriving with `?auto=1` shows the pop-up ("Starting the best source", a bar, Cancel / click outside / Escape) unless laev's auto-pick is `off` (`Watch.auto_start?/1`; unset = on). The address is cleaned at once, so Back or a reload only lists. When found: Browser device → `push_navigate` to the player page; External player → the app is launched and the page stays (panel + list). Cancelled or off → the releases are listed (Play / External per release, Load more, Retry).
3. `/watch/movie/:id`, `/watch/tv/:id/:season/:episode?h=<info hash>` (`WatchLive`) — the player page (video + subtitle sidebar). `h` names the release; without it the best is chosen and the address is updated (`push_patch replace`) to name it, so the URL can be copied, reloaded, and Back returns to the sources. A shared URL looks for the hash among the checked releases (a few extra pages) and falls back to the best. Progress goes through laev as before; the next episode autoplays when laev's autoplay is on.

Shared pieces: `Roki.Watch.Resolver` (find/probe/pick/failure texts), `RokiWeb.WatchComponents` (mode switch, release list, external panel, pop-up). `test/e2e/flow.js` and `flow2.js` are the manual end-to-end runs (they use a real debrid account and a session cookie in `/tmp/e2e-cookie.txt`; clean up history, the source cache and the remux directory afterwards).


## The study player (`/watch/...`)

`RokiWeb.StudyComponents.study_player/1` + `assets/js/study/sidebar.js` (`StudySidebar` hook), after
the idea of `alexdont/debrid_theatre`. Any number of tracks can be on at once, in any order: the first (★) is the **studied** one (words, the
list's lines), the others show under it as translations in the overlay and the list ("Peek" blurs them until
clicked). The slim bar under the player has **Subtitles** (a menu: what is on, in order, with ↑/✕ per row, then
the languages to add — a language with several versions opens to them), **Settings** (timing ±0.25 s,
text size, Study, Peek, audio), **Lines**, theater and fullscreen; menus open upward over the picture, as
bottom sheets on a phone, and on a phone the list of lines is a sheet too (`data-sheet`; `data-panel`
and theater are for ≥1024px) (`apply/selection/restore` in sidebar.js); remembered by name and language in `roki:study:layers`. A word in *any* line looks up in
that line's own language (`data-lang`).
Subtitles are drawn by the hook (`.study-overlay`), not native text tracks. Every word of a
language with a dictionary is a `.study-word`: hover 300 ms → the video pauses and a card shows
(`/dict/:lang?q=` → `RokiWeb.DictController`, `Roki.Dictionary`: Jisho for Japanese, Wiktionary
for the rest; cached a day, rate-limited); leaving resumes it; a click/tap pins it. Japanese is cut
with **Kuromoji** (`priv/static/vendor/kuromoji.js` + 17 MB `priv/static/kuromoji/dict`, loaded
the first time a Japanese track shows; until then `Intl.Segmenter` + `joinInflections`) and
looked up by the dictionary form (`basic_form`: 食べ → 食べる). The list rows have the words, the
translation and a ▶ (only ▶/the time seeks, so text can be selected). Tools: sync offset ±0.5 s
(per release), caption size, "Study" (pause after every line, ⟲ replays it), theater, fullscreen
(the stage, so the overlay stays). UI state (`data-theater`, `data-panel` = open/compact/closed,
`data-peek`) lives on `#study-ui` (`phx-update="ignore"`) and in localStorage (`roki:study:*`).
Extra tracks: `Watch.external_langs/3` — the user's language, and for anime with a Jimaku key
the original Japanese; each in its own async (`{:ext_subs, lang}`) appended to
`data-player.tracks`. Japanese for anime is `Watch.jimaku_tracks/4`: *every* plausible Jimaku file
for the episode (they differ in timing), the one from the release's own group first, labelled by
group. The matching MAL season is the ctx (`search_title` = romaji, `episode` = the episode of that
MAL entry).

**Next episode** (`Watch.next_episode/4`: the next one out in the season, else the first of the next season,
with the "S2E1" tag). The player bar's **Next** button (watch page) sends `next`; the page goes to the next
episode's watch address with `?prefer=<hash>` — a hint: the release that was playing is kept if it is among the
first few checked (a season pack is), else the best starts. The sources page has the same for an external
player: a button in the header and a big **Play next episode** in the open-in-VLC panel, going to
`/sources/tv/…?auto=1&prefer=…`; pressing it there marks the current episode watched (an external player cannot
report progress). **Audio** (`audioList/setAudio` in sidebar.js) works on hls.js and on a native `audioTracks`
list, shows a bar button only when there are two or more, and remembers the choice by name.
